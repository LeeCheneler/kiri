# Kiri workspace instructions

This repository contains workflows, bundles, prompts, and configuration for
Kiri. Keep project guidance in `AGENTS.md`; `CLAUDE.md` imports it for Claude Code.

## Before changing workflows

- Read [the workflow authoring reference](docs/workflow-authoring.md) for the
  relevant feature before editing a workflow, bundle, prompt, article, or
  summary. It contains the full schema, examples, and execution contract.
- Inspect neighbouring workflows and each bundle's README for local patterns.
- Use `.kiri/workflow.schema.json` and `.kiri/kiri.schema.json`, generated by the
  installed Kiri, to verify the current schema. If a reference disagrees with
  the installed schema, follow the schema and update the reference.
- Workflows live directly in `workflows/*.yaml`; nested definitions are ignored.
  Reusable bundles live in `bundles/<name>/run.sh`, with an executable script
  and a README describing the environment contract.

## Execution constraints

- Steps run on the host machine in a per-run scratch directory. Use
  `KIRI_REPO_ROOT` and `KIRI_BUNDLE_DIR` for workspace and bundle files.
- Step environments are scoped. Declare required variables explicitly; never
  assume shell credentials are inherited, read secret files, or commit secrets.
  Configuration credentials use `{ env: NAME }` references.
- Inline `sh:` uses POSIX `sh`. Start non-trivial scripts with `set -eu` and
  account for macOS/BSD utilities. Do not use bash-only syntax in inline steps.
- Pass data via declared env refs to an earlier step's `id`, named output, or
  article. Only the immediately preceding main step's stdout is also stdin;
  articles and summaries receive empty stdin.
- Use configured `provider:model` identifiers for LLM steps. Do not invent a
  provider or model; follow workspace preferences and existing workflows.
- Validate changes before running a workflow. A workflow can publish content,
  spend money, or modify repositories; run one only when its effects are
  authorized by the task.

## Session instructions

Kiri loads workspace `kiri.md`, then project instructions, then the `AGENTS.md`
chain for a session's working directory inside its allowed directories.
Keep workspace-wide session preferences in `kiri.md`. This file governs work
in this repository; the long authoring guide is read when needed.
